# dsh-cooper-memory

给 DeepSeek Harness 的**本地记忆 + 文件夹知识库**。数据只有一个 SQLite 文件，不依赖 Docker、不依赖向量服务；除了调用你已配置的模型通道做蒸馏，进程不对外发起任何请求。

## 它解决什么

DSH 每个新会话都从零开始。这个插件在本地维护一份可核对、可回滚的记忆，并解决三件事：

1. **跨会话记忆** —— 保存你确认过的身份、偏好、环境事实，每轮自动带上相关部分
2. **文件夹知识库** —— 任意目录递归入库，保留原始层级，检索以分块为单位
3. **可编辑的检索分块** —— 每次修改留版本，可逐行比对、可回滚

## 工作方式

```
对话 ──► DSH 写会话日志（~/.dsh/sessions/*.zstd）
              │
              ├─ 蒸馏（阈值 6 轮 / 静默 300 秒触发）
              │     └─► L1 事实（pending，待你确认）
              │              ├─ 聚类 ─► L2 场景块
              │              └─ 归纳 ─► L3 画像
              │
              └─ 注入：每轮把「画像 + 场景 + 相关事实」合成一条消息，排在用户消息之前
```

**三层记忆的分工**：

| 层 | 是什么 | 怎么进上下文 |
|---|---|---|
| L3 画像 | 400 字以内的稳定描述（身份/技术栈/工作偏好） | 每会话一次，变了才重发 |
| 知识库片段 | 本地文档库里与问题相关的块，带来源路径 | 查询命中才注入，默认 2 块 |
| L2 场景 | 同主题若干条记忆压成的一篇文档 | 查询命中才注入 |
| L1 事实 | 单条偏好/事实/待办 | 查询命中才注入，最多 6 条 |

## 三条硬规则

**① pending 不注入**

蒸馏有噪声，所以结果一律进 `pending`。你确认后才变 `active`，才参与召回。自动蒸馏跑得再勤，也不会把没验证过的东西塞进上下文。

**② 拒绝留抑制记录**

被拒的内容保留正文，参与后续去重——同一件事不会反复被提取、反复问你。

**③ 新说法不立刻顶掉旧说法**

新的推断只挂 `supersedes` 链接，**确认时才替换**，旧条目转为 `superseded` 但保留在链条里，随时可查"什么时候被谁取代的"。

## 召回的两道质量控制

没有这两道，一句"你好"就能召出一堆噪声：

1. **jieba 切词 + 停用词表** —— 寒暄、虚词、万能词（"帮我""看看""功能"）不参与匹配
2. **有效词下限** —— 有效词少于 2 个时只注入画像，不做匹配召回

另外查询用**最近 3 轮**拼接，不只用最新一条——否则话题转移后召回就失效了。

## 自动蒸馏的触发

| 触发 | 条件 | 默认 |
|---|---|---|
| 攒够阈值 | 本会话新增轮次 ≥ 生效阈值 | 稳态 6 |
| 渐进爬坡 | 每次成功后阈值翻倍 | 1 → 2 → 4 → 6 → 毕业 |
| 闲置兜底 | 静默超过 N 秒仍有未蒸馏轮次 | 300 秒 |
| 扫描频率 | 定时器检查间隔 | 30 秒 |
| 失败退避 | 指数退避，避免卡在坏会话上烧 token | 30s → 60s → … 上限 10 分钟 |

## 存储

```
~/.dsh-memory/
├─ mem.db                  SQLite（WAL）：文档/分块/版本/记忆/场景/成本
├─ memories.journal.jsonl  只增事实源，可用 rebuild 重放整张记忆表
└─ inject-trace.log        每步一行：inject / skip / error / autodistill
```

**为什么双写**：SQLite 是检索用的派生视图，JSONL 是事实源。库损坏时 `rebuild` 能把记忆表原样重放回来（实测 1278 条一致）。

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `MEM_ROOT` | `~/.dsh-memory` | 数据目录 |
| `MEM_DB` | `$MEM_ROOT/mem.db` | 数据库路径 |
| `MEM_WEB_PORT` | `17890` | 界面端口 |

模型通道：**包里没有内置任何默认地址、模型或凭据名**。三项分别来自 `LLM_BASE_URL`/`DEEPSEEK_BASE_URL`、`LLM_MODEL`、`LLM_KEY_ENV`，或 profile 里 `agent-default-model` 指向的那个 provider。缺任何一项直接报错，不会退回到某个写死的地址。凭据文件只解析点名的那个 ref，其余条目不进内存。

## 使用

安装后：

- **自动**：每轮对话前自动注入相关记忆，无需任何操作
- **界面入口**：装了 dsh-better-sidebar 就在右侧栏开始页的卡片里；没装则在左侧栏的「记忆」图标处；两者都指向同一个本地界面 `http://127.0.0.1:17890`
- **工具**：20 个 `mcp__dsh-cooper-memory__*`，用于主动检索、写记忆、管理场景
- **命令行**：`dsh-cooper-memory --help`

界面上有：目录树、检索、分块编辑/比对/回滚、待确认记忆队列、场景块浏览、成本统计。

## 边界

- 只做词面检索（FTS5 + jieba），没有向量；语义相近但用词不同的内容可能召不到
- 只解析纯文本类文件（md / txt / csv / json / yaml），PDF 与 DOCX 需先转换
- 自动提取是**辅助**，pending 队列才是质量闸门
- 单机单库，没有多租户与同步
